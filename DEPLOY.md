# Deploying Card Coach (always-on public URL)

The app is a plain Node/Express server with no database — it deploys to any
Node host. It's **already deployed on Render** at
https://mtg-card-explainer.onrender.com (paid Starter, always-on). These steps
document that setup. Railway/Fly/Koyeb work too; see the note at the bottom.

## What's already set up

- `server.js` listens on `process.env.PORT` and `0.0.0.0` — host-ready.
- `render.yaml` — a Render Blueprint (build/start commands + env vars).
- `.node-version` pins Node 22.
- `cache/` **is committed on purpose** (see below).

## Code on GitHub (done) + how to ship updates

The code lives at `github.com/chhristopher/mtg-card-explainer`, the local repo's
`origin` remote is configured, and Render auto-deploys on every push to `main`.

**Day-to-day workflow uses GitHub Desktop** (simplest for the owner):

> edit files → **Commit to main** → **Push origin** → Render auto-deploys in ~2 min.

(CLI equivalent: `git add -A && git commit -m "…" && git push`.)

## Deploy on Render

1. Go to **dashboard.render.com → New + → Blueprint**.
2. Connect your GitHub and pick the `mtg-card-explainer` repo. Render reads
   `render.yaml` automatically.
3. It will prompt for the one secret: **`ANTHROPIC_API_KEY`** — paste your key.
   (`EXPLAINER_MODEL` is preset to `claude-sonnet-4-6`; change it here for
   `claude-opus-4-8` max accuracy or `claude-haiku-4-5` to save cost.)
4. Click **Apply**. First build takes a few minutes. You'll get a public URL
   like `https://mtg-card-explainer.onrender.com` — share that / make a QR code.

That's it. No key set = the app runs in demo mode (safe to preview), so even a
misconfigured deploy won't break or bill anything.

## The cache is your accuracy store — keep it in git

Hosts give you an **ephemeral disk**: anything the running app writes to `cache/`
is wiped on the next redeploy. So the *committed* cache is the real source of
truth for your hand-reviewed explanations.

Workflow to lock in a reviewed explanation: generate + review locally
(`npm start`), edit the JSON in `cache/` to fix wording, then commit & push the
`cache/` change (GitHub Desktop, or the CLI below). autoDeploy ships it live.

```bash
git add cache/ && git commit -m "Review: fix <card> explanation"
git push          # autoDeploy ships it to the live site
```

Explanations generated by the *live* server are still cached for that running
instance (fast + cheap for repeat lookups), they just don't survive a redeploy
unless you commit them.

## Plan: paid Starter (no cold starts)

This service runs on Render's paid **Starter** plan specifically to avoid cold
starts — the free plan spins down after ~15 min idle and the next visitor waits
~30–50s, which was a dealbreaker mid-game. (Heads-up: `render.yaml` still lists
`plan: free`; the dashboard setting is what actually runs, so that line is stale.)

## Other hosts

- **Railway**: New Project → Deploy from GitHub repo → add `ANTHROPIC_API_KEY`
  var. No `render.yaml` needed; it auto-detects `npm start`.
- **Fly.io**: `fly launch` (auto-detects Node), then
  `fly secrets set ANTHROPIC_API_KEY=...`.
